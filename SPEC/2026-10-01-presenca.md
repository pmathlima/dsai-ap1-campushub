# Registro e Controle de Presença

## O quê e por quê

Mecanismo para atestar formalmente que o aluno participou do evento acadêmico. O registro de presença é o pré-requisito indispensável para autorizar avaliações do evento e futura certificação.

## Funcionalidades

- Consulta da lista de presença pelo Organizador.
- Registro manual de presença pelo Organizador para participantes inscritos.
- Registro de presença pelo próprio Aluno mediante código de check-in fornecido pelo Organizador.
- Consulta de status de presença pelo Aluno em sua lista de inscrições.

## Regras de negócio

1. A presença só pode ser registrada para alunos com inscrição no status `CONFIRMADA`.
2. A presença só pode ser aberta e registrada durante a janela do evento: a partir de 15 minutos antes da `dataInicio` até 2 horas após a `dataFim`.
3. O Organizador pode marcar ou desmarcar a presença de qualquer inscrito confirmado a qualquer momento dentro da janela permitida.
4. O código de presença (_check-in code_) é uma string alfanumérica de 6 caracteres gerada pelo organizador para autoatendimento do aluno.
5. Uma presença marcada como confirmada não pode ser duplicada.
6. Apenas eventos no status `PUBLICADO` ou `CONCLUIDO` permitem consulta ao histórico de presença.

## Dados envolvidos

- `Presenca`:
  - `id`: string (UUID v4)
  - `inscricaoId`: string (FK para Inscricao, único)
  - `eventoId`: string (FK para Evento)
  - `alunoId`: string (FK para Usuario)
  - `presente`: boolean (default: false)
  - `registradoPor`: enum (`ORGANIZADOR`, `AUTO_CHECKIN_ALUNO`)
  - `dataCheckin`: datetime (opcional, ISO 8601)
- Atributo no `Evento`:
  - `codigoCheckin`: string (opcional, 6 caracteres alfanuméricos)
  - `checkinAberto`: boolean (default: false)

## Fluxos

- **Check-in pelo Aluno:**
  1. Aluno autenticado envia o código de check-in para o `eventoId`.
  2. Sistema valida se a janela de presença está aberta e se o código confere.
  3. Sistema valida se o aluno possui inscrição `CONFIRMADA`.
  4. Registro de presença é atualizado para `presente = true` com `dataCheckin = agora`.
- **Registro Manual pelo Organizador:**
  1. Organizador visualiza a lista de inscritos.
  2. Organizador marca um ou mais alunos como "Presente".
  3. Sistema atualiza os registros de presença dos respectivos IDs.

## Critérios de aceitação

- [ ] Auto-check-in do aluno rejeitado com código HTTP 400 se o código informado for incorreto.
- [ ] Auto-check-in rejeitado se realizado fora da janela temporal estipulada.
- [ ] Não permitir marcar presença para inscrição com status cancelado (HTTP 422).
- [ ] Registro manual pelo organizador comanda atualização imediata e auditável (`registradoPor = ORGANIZADOR`).
- [ ] Aluno autenticado só consegue consultar o status de presença de suas próprias inscrições.

## Casos de erro

- `JANELA_CHECKIN_FECHADA`: tentativa de registro antes ou depois do período permitido.
- `CODIGO_CHECKIN_INVALIDO`: código alfanumérico incorreto ou não gerado.
- `INSCRICAO_INVALIDA_PARA_PRESENCA`: inscrição cancelada ou inexistente para o usuário.
- `PRESENCA_JA_REGISTRADA`: tentativa redundante de registrar presença já computada.

## Permissões

- **Aluno:** Realizar auto-check-in em evento no qual está inscrito; visualizar status de sua presença.
- **Organizador:** Abrir/fechar check-in, gerar código e alterar manualmente presença de inscritos em seus eventos.
- **Admin:** Visualizar e auditar presenças de qualquer evento.

## Fora do escopo

- Leitura automatizada por QR Code via câmera web/mobile nativa.
- Validação de presença baseada em cerca geográfica (geolocalização / GPS).
